# 硕士学位论文智能评审系统 v2.5

**核心设计原则**：Python负责可量化、LLM负责深度评价——各司其职，输出稳定可解释的评审报告。

---

## 核心架构

```
docx/PDF文件
    ↓
[1] 文档解析层 (Python)
    │   - 提取：封面、摘要、章节、参考文献
    │   - 输出：ThesisModules 结构
    ↓
[2] 精准统计层 (Python)
    │   - 字数统计（总字数、各章节字数）
    │   - 文献统计（总数、语种、年份、期刊占比）
    │   - 论文类型检测（5种类型识别）
    │   - 表格/图表数量
    │   - 输出：统计数据 + 论文内容摘要
    ↓
[3] 深度评价层 (LLM)
    │   - 读取Python统计数据 + 论文内容
    │   - 按7维度逐项深度评价
    │   - 引原文作为评价依据
    │   - 生成修改建议（分高/中/低优先级）
    ↓
[4] 报告生成层 (LLM)
    │   - 生成结构化评审报告
    │   - 输出：评审报告.md + 评审数据.json
    ↓
输出：评审报告.md + 评审数据.json
```

### 关键设计

| 模块 | 技术 | 职责 |
|------|------|------|
| 文档解析 | pdfplumber/docx | 提取结构化文本、章节、参考文献 |
| 精准统计 | **Python规则** | 字数、文献数、论文类型等可量化指标 |
| 深度评价 | **LLM** | 创新性、逻辑性、方法严谨性等深度评价 |
| 报告生成 | LLM | 生成完整结构化评审报告 |

| 7. 结论与建议 | 5-10% | 结论明确性、建议可操作性、局限性说明 |

## 文档解析策略（分层模块化解构）

### 核心思想

论文解析采用**分层模块化**策略，将论文拆分为独立的结构单元，再按需重组。这种方法比按章节评价更灵活，能支持多维度评价。

### 模块划分

| 模块类型 | 识别方式 | 内容 |
|---------|---------|------|
| **封面** | 论文开头特定标记 | 标题、作者、学校信息 |
| **摘要** | `摘  要`/`摘要` 标记 | 中英文摘要分开提取 |
| **目录** | `目  录`/`目录`/`CONTENTS` | 标记已识别 |
| **正文** | `第X章` 标题模式 | 按章节拆分 |
| **参考文献** | `参考文献`/`References` | 从标记位置开始提取 |
| **致谢/附录** | 特定标记 | 在参考文献之后 |

### 章节识别规则

```python
# 章节标题识别模式（按优先级）
CHAPTER_PATTERNS = [
    r'^第([一二三四五六七八九十\d]+)章\s+(.+)$',  # 第1章 绪论
    r'^([1-9])\.\s+([A-Z][^\d]+)$',               # 1. Introduction
    r'^[12][0-9]*\.\s+',                          # 10. 章节
    r'^[1-9]\d*(\.\d+)?\s+[A-Z\u4e00-\u9fff]',    # 1.1 章节标题
]
```

### PDF解析关键技术

1. **逐行提取 + 位置追踪**
   - 按页面逐行提取文本
   - 记录每行的页码、行号
   - 支持准确定位章节边界

2. **多行标题合并**
   - 论文标题常分2-3行显示
   - 从`论文题目：`开始，收集后续短行直到遇到分隔标记
   ```python
   # 示例：封面标题分两行
   # "论文题目：河南省农业绿色韧性的时空差异"
   # "及影响因素研究"
   ```

3. **重复章节去重**
   - PDF排版问题：同一章节标题可能重复出现
   - 方案：跟踪上一个章节号，若相同则只追加内容，不创建新章节

4. **摘要检测容错**
   - 常见变体：`摘  要`、`摘要`、`摘 要`
   - 方案：统一归一化后匹配
   ```python
   text.replace(' ', '').replace('　', '') == '摘要'
   ```

5. **参考文献识别（关键难点）**
   - 从`参考文献`标记后开始提取
   - 遇到`致谢`、`附录`时停止

   **多行合并策略**：
   - PDF中参考文献常跨多行（如作者、标题、期刊跨3-4行）
   - 判断依据：新行是否以`[数字]`或`[J]`开头
   - 若不以标记开头，则认为是上一条的延续行

   **验证规则**：
   ```
   有效引用必须满足以下之一：
   - 开头为 [数字] 如 [1], [2]
   - 开头为 数字. 如 1. Author
   - 英文作者开头如 Smith, J.

   拒绝以下情况：
   - 仅 [J]. 开头（片段，不是完整引用）
   - 太短的行（<15字符）
   - 纯数字、章节标题等
   ```

   **清理规则**：
   - 移除末尾页码如 `.75` → 清理为干净引用
   - 移除末尾多余点号

### 参考文献提取代码模式

```python
class PDFParser:
    def _is_new_reference_start(self, text: str) -> bool:
        """判断是否是新引用条目的开始"""
        # [1] 编号格式
        if re.match(r'^\[\d+\]', text):
            return True
        # 数字. 格式
        if re.match(r'^\d+\.\s', text):
            return True
        return False

    def _is_valid_reference(self, text: str) -> bool:
        """验证是否为有效引用"""
        # 必须有编号开头
        if not re.match(r'^\[\d+\]', text):
            return False
        # 拒绝片段如 [J].期刊名
        if re.match(r'^\[J\]\.', text):
            return False
        return True

    def _clean_reference(self, text: str) -> str:
        """清理引用末尾的页码等"""
        # 移除末尾 .75 类型的页码
        text = re.sub(r'\.\d{1,3}$', '', text)
        return text.strip().rstrip('.')

    def _extract_back_matter(self, modules):
        """提取参考文献（多行合并）"""
        ref_started = False
        current_ref = ""

        for line_info in self.lines:
            text = line_info['text'].strip()

            if '参考文献' in text:
                ref_started = True
                continue

            if ref_started:
                # 遇到致谢/附录停止
                if text_no_space == '致谢' or text == '附录':
                    if current_ref and self._is_valid_reference(current_ref):
                        modules.references.append(self._clean_reference(current_ref))
                    break

                # 判断是否新条目
                is_new = self._is_new_reference_start(text)

                if is_new:
                    # 保存前一条
                    if current_ref and self._is_valid_reference(current_ref):
                        modules.references.append(self._clean_reference(current_ref))
                    current_ref = text
                else:
                    # 续接前一条
                    current_ref += text
```

### 注意事项

1. **PDF vs DOCX差异**
   - DOCX：结构化XML，可直接读段落
   - PDF：纯文本，需自己重建结构
   - pdfplumber提取的文本会丢失部分格式信息

2. **页眉页脚干扰**
   - 封面页可能有罗马数字页码
   - 正文页可能有章节名页眉
   - 需在解析时跳过前N行/特定位置

3. **表格和图表**
   - 当前实现仅提取纯文本
   - 表格内容可能乱序
   - 如需分析表格，需额外处理

4. **特殊字符处理**
   - 中文标点 vs 英文标点
   - 全角 vs 半角
   - 上下标、公式可能无法正确提取

## 评审流程

```
[1] 文档解析（Python）
    ├── PDF: pdfplumber 逐行提取
    ├── DOCX: zipfile XML解析
    ├── 提取：封面、摘要、目录、章节、参考文献
    └── 输出：ThesisModules
    ↓
[2] 精准统计（Python）
    ├── 字数统计：总字数、各章节字数
    ├── 文献统计：总数、语种分布、年份分布、期刊占比
    ├── 论文类型：基于方法关键词识别5种类型
    ├── 表格数量：表格数、图数量
    └── 输出：统计数据 + 论文内容摘要
    ↓
[3] 深度评价（LLM）
    ├── 读取Python统计数据 + 论文内容
    ├── 按7维度逐项深度评价
    ├── 引原文作为评价依据
    └── 输出：各维度评价结果
    ↓
[4] 报告生成（LLM）
    ├── 综合统计数据 + LLM评价结果
    └── 输出：评审报告.md + 评审数据.json
```

**架构说明**：
- 步骤[1]-[2]由Python自动执行，无需LLM介入
- 步骤[3]-[4]由LLM执行，读取Python统计数据后进行深度评价
- 最终输出：评审报告.md + 评审数据.json
